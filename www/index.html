Upstream DNS

    

     
     
     

     
     
Allowed queries go to this server over an encrypted connection (port 853), so your ISP can't read or change them. Replaces the address and backup above while on. Examples: dns.quad9.net, one.one.one.one, dns.google.

     
With a backup, each query goes to both at once and the first answer wins: no waiting when one is down or slow. Both providers then see your queries.

     

    
Ads still showing on some devices?
     
Devices also get DNS servers over IPv6 from the router, and use them instead of this one. In the router, turn off IPv6 DNS advertisement (RDNSS/DHCPv6) or point it at this device. Also switch off "Secure DNS" / "DNS over HTTPS" in browsers, which bypasses every local DNS server.

     
This device also answers DNS over IPv6, at the addresses shown under Network on the overview.

   
Backup and restore

    
One file with your settings, custom lists, local names, Wake-on-LAN computers and device rules. Use it after a fresh install or to move to another board.

    

    

    
Restoring replaces those settings and restarts the device. Passwords missing from the file stay as they are.

   
Status LED

    
Shows the device state on the board's LED: setup (slow yellow), no Wi-Fi (very slow teal), updating (blue), failure (fast red), paused (orange flash), all good (dim green or off). Boards wire their LED differently, so pick yours.

    

     

      

      

     
     

   
DHCP server

    
Only for routers whose DNS setting can't be changed. Give this device a static IP, turn off DHCP in the router, then turn this on: devices get addresses from here, with the router as gateway and this device as DNS. Two DHCP servers on one network cause conflicts.

    

     

     
Up to 64 addresses, outside the range the router used to hand out.

     
Some routers never pass address requests on to Wi-Fi devices. If "requests seen" stays at 0 while a device is trying to connect, this can't work with your router.

     

   
Local names

    
Give devices on your network a name, or send every name under a suffix (like lan or in-addr.arpa) to another DNS server such as your router, so its device names and reverse lookups work.

    

    

   
Extra protection

    

     
     
Answers the official signals so Firefox turns off its automatic DNS-over-HTTPS and Apple turns off iCloud Private Relay on this network.

     
     
Stops apps from looking up Google, Cloudflare, Quad9 and other DNS-over-HTTPS servers. A phone with "Private DNS" set to one of them loses Internet until it is set to Automatic or Off. Allowed domains still pass.

     
     
Some trackers sit on a subdomain of the site (metrics.shop.com) that points to a tracking company. Answers whose aliases (CNAME) lead to a blocked domain are blocked too.

     
     
     
     
For families: explicit results are filtered for every device on the network and can't be turned off in the browser. Stays on while ad blocking is paused.

     
     
A device that floods DNS (a loop, malware, a broken app) gets REFUSED for the rest of the minute, so it can't slow down everyone else. 1000 is plenty for any normal device.

     
     
Hidden data is never stored: the query log, top lists and client list stop showing it. Blocking and per-device rules keep working.
